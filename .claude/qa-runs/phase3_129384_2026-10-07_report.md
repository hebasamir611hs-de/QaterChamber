Per the instruction it was not started again. **So no finding below is CONFIRMED; each is a candidate with the evidence listed.**

1. **Weather configuration — INCONCLUSIVE, NEEDS USER.** Root cause: the Weather card isn't configurable in the CMS. TCs: 135951 (partly), 135962, 135968, 136049–136056, plus the Weather part of 135965 and 136067.
   - There's no Weather object on the Object Authoring index and no Weather entry on `manage-dynamic-widget`. The card is the `qc-weather-widget` client extension, which is always rendered.
   - PBI US002 says "manage the dynamic widgets on the Home Page (Weather, Marhaba Guide, B2B)" and "Weather Widget once configured based on the integrated API will reflect the details accordingly".
   - But the same story's Administrator Workflow step 3 says "Selects the widget to configure: Marhaba Guide, or B2B Platform".
   - The PBI is ambiguous, so per Rule 3 this isn't a bug. The BA needs to decide.
2. **Weather API hang → no fallback — candidate PRODUCT_BUG (P2), INCONCLUSIVE until a manual screenshot.** TC: 136058.
   - With the API request held open, the card stayed on the loading skeleton for 75 s, in 2 of 2 automated runs.
   - Source: `/o/qc-weather-widget/qc-weather.js?v=2` calls `window.fetch(API_URL, ...)` with no timeout or AbortController. There is no retry or refresh timer either; it re-renders only on page load or Senna navigation.
   - PBI: "if the Weather API is unavailable the Weather Widget shall display: 'Weather data unavailable.'"
   - TC 136058: "After the timeout threshold, 'Weather data unavailable.' displays; no infinite spinner remains."
   - Caveat: the provider (Open-Meteo) is called server-side by the qc-weather-rest wrapper. My simulation hangs the browser-to-wrapper call.
3. **Widget row gap 32 px vs Figma 24 px — candidate UI finding (P3).** TCs: 135930, 135938, 135939.
   - Figma node 849:15904: Frame 112 is 1320 x 362, gap 24; the cards are 424 x 362.
   - Live at 1920 px, with the feed limited to the PBI's two widgets: column and card width 418.67 px.
   - That's 5.33 px over the ±5 image tolerance, and the gap is 8 px over the ±2 layout tolerance.
   - Fragment CSS: `.qc-home-dynamic-widgets { --_dw-gap: 32px }`.
   - One root cause.
4. **Redirect URL limit 280 < US 500 — Rule 5.3, NEEDS USER.** TCs: 135990, 136028. 501/510 are refused, so 135989 and 136027 pass.
   - A 500-character URL is refused: "Object entry value exceeds the maximum length of 280 characters for object field redirectUrl". The input has no `maxlength`.
   - Rule 5.3 says a shorter implemented limit is a bug for Alaa. The 2026-10-03 standing note says char-limit cases are N/A and never bugs.
   - The user needs to decide which applies.
